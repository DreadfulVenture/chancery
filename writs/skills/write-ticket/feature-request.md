# Feature request tickets

**Scope.** This covers feature requests: someone wants the product to do something it doesn't do. This ticket doesn't
decide, design, estimate, or add any timeline. The build hasn't been decided, so anything in the ticket that says how it
gets built has made the decision for the person picking it up, and getting past it means arguing with the ticket's own
words. The requester's pictured solution stays in the record, marked as theirs and goes no further.

## An example

A feature request might read:

> ### The account payment shows when escalating a ticket
>
> As a support agent escalating a ticket, I can see what the account pays without leaving the escalation, so I can say
> what the account is while I'm writing the ticket instead of switching to the billing app mid-escalation or guessing.
> Skipping the check has put free-trial accounts on the priority path more than once.
